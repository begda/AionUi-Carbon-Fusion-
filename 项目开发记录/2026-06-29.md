## AionCore 后端启动修复

### 做了什么

修复开发模式下 AionCore（后端核心）无法启动的问题。

### 解决的问题

`bun run dev` 启动后，AionCore 报错：
```
BackendStartupError: aioncore startup failed while resolving backend binary
当前安装缺少必要的本地资源，AionCore 无法启动。
```

### 踩的坑

1. **`process.resourcesPath` 在开发模式下不存在**
   - `binaryResolver.ts` 只依赖 `process.resourcesPath` 定位 bundled-aioncore 目录
   - 但 `process.resourcesPath` 是 Electron 在打包模式下填充的，开发模式下为 `undefined`
   - 之前尝试用 `??` 回退 `app.isPackaged` 判断，但由于 `import { app } from 'electron'` 在构建后的代码中可能异常，导致回退没有触发
   - 最终方案：使用 `__dirname`（指向 `out/main/`）回溯到项目根目录的 `resources/`

2. **Electron 单实例锁冲突**
   - 系统中已安装的正式版 `AionUi.app` 占用了单实例锁
   - 开发实例启动时被阻止，一直报 `Another instance is already running`
   - 解决：退出正式版 AionUi

3. **构建缓存导致修改未生效**
   - 多次修改 `binaryResolver.ts` 但没有清理 `out/` 目录
   - 构建工具使用了缓存，旧代码仍然生效
   - 解决：`rm -rf out/main out/preload out/renderer` 清理缓存

### 最终方案

修改文件：`packages/desktop/src/process/backend/binaryResolver.ts`

```typescript
// 新增 resolveDevResourcesPath()：用 __dirname 回溯定位开发模式的资源目录
function resolveDevResourcesPath(): string | undefined {
  const candidate = resolve(__dirname, '../../resources');
  if (existsSync(candidate)) return candidate;
  const cwdCandidate = join(process.cwd(), 'resources');
  if (existsSync(cwdCandidate)) return cwdCandidate;
  return undefined;
}

// 新增 resolveResourcesPath()：优先检查 process.resourcesPath 中是否真有 bundled-aioncore
function resolveResourcesPath(): string | undefined {
  const rp = process.resourcesPath;
  if (rp && existsSync(join(rp, 'bundled-aioncore'))) return rp;
  return resolveDevResourcesPath();
}
```

## 环境准备工作

### 踩的坑

1. **Electron 镜像问题**
   - 国内网络无法直连 GitHub 下载 Electron 二进制文件
   - 解决：设置 `ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/`

2. **正式版 AionUi 冲突**
   - 系统中安装的 `/Applications/AionUi.app` 占用 Electron 单实例锁
   - 开发服务器启动时被阻止
   - 解决：先用 `pkill -9 -f "AionUi"` 终止正式版，可改用 `bun run start:multi` 跳过单实例锁

3. **AionCore 下载**
   - `bundled-aioncore` 目录缺失需要运行 `node scripts/prepareAioncore.js` 下载
   - 下载需要 GitHub 访问，同理使用镜像
